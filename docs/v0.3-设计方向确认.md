# v0.3：先确认设计方向

v0.3 将新项目拆成“实际方向稿 → 用户确认 → 完整实现与审查”。目的是在铺开全部内容之前，让使用者先看到字体、素材和构图是否适合；它不保证每次生成都符合个人审美。

## 工作台怎么用

1. 新建项目并发送需求，尽量给出用途、使用者、真实内容和主要功能；没有风格偏好也能开始。
2. Agent 编辑真实 `index.html`，记录 `DESIGN.md` 与 `DESIGN_PLAN.json`。展示型页面先做桌面首屏、一个代表性中段及响应式手机布局；工具页可以用一个主要任务区域表达方向。
3. 在“设计方向”查看电脑首屏、中段和手机的实际截图，以及艺术方向、字体、构图和素材说明。方向稿还不是完整网站，批准前不铺开整站或后端。
4. 不满意就点击“调整设计方向”并发送要求，形成新的方向稿；满意后点击“按此方向完善网页”，Agent 再完成其余页面内容和静态功能。关键素材缺失、预览不全或已过期时，先处理问题再确认。
5. 完整制作后进行七项电脑与手机截图审查，必要修订后重新渲染；随后继续提出具体修改或下载源码。

已确认方向后，“只换按钮文字”“保留布局增加搜索”等范围明确的修改直接执行。旧项目也保留直接修改的方式；需要整体更换视觉时，点击“重新定设计方向”并说明要求，就会先产出方向稿并等待确认。重新设计保留真实内容和有效交互。旧的模型自审结果不能否定用户的新反馈。

## 哪些记录会保存

- `DESIGN.md`：一句艺术方向及取舍，字体角色与中文光学校正、主图和标题的比例与裁切、素材就绪程度、章节节奏、手机安排和运动作用。
- `DESIGN_PLAN.json`：宿主规定结构的方向计划，包含本轮方向编号及素材状态。确认针对这份实际计划和预览；重新设计后不能批准旧编号。
- 每轮证据：计划快照、真实截图和渲染诊断，与当前网页文件分开保存。
- `DESIGN_REVIEW.json`：完整实现后的七项具体观察、实际修订与尚未解决的问题。方向阶段不靠生成“美感通过”报告代替用户确认。

七项维度保持为用途与表达、信息层级、字体与阅读、色彩与对比、构图与留白、视觉个性、移动端与操作。审查更加具体地观察字面和间距、中文断行、图像与标题的关系、素材的光线和空间环境，以及各章节的强弱变化。[设计标准](./美感设计标准.md)说明判断方法与证据边界。

## 本机接口

这些接口供本机工作台调用，不是远程服务。写入请求使用 JSON，并带 `X-Requested-With: web-dev-agent`；沿用服务的同源检查。通常直接使用中文工作台即可。

| 请求 | 用途 |
| --- | --- |
| `POST /api/projects/:id/messages`，`{"message":"网页需求"}` | 按项目当前阶段提交需求。新项目先做方向；等待确认时用于调整方向；已确认或旧项目的普通修改直接实现。 |
| 同上，增加 `"mode":"design"` | 显式启动新的设计方向；旧项目整体换风格也使用此方式。 |
| `POST /api/projects/:id/approve-design`，`{"designId":"当前方向编号"}` | 确认当前可用方向并启动完整实现。方向未就绪、已失效或文件变化时不能确认。 |
| `GET /api/projects/:id` | 读取项目、文件、对话、运行记录及 `design` 摘要；摘要包括当前方向、计划、预览是否存在、问题及能否确认。 |
| `GET /api/projects/:id/design-image?view=desktop` | 读取当前方向的电脑首屏图；`view=detail` 为代表性中段，`view=mobile` 为手机图。 |

发送与确认接受后，任务在后台执行，工作台通过已有的项目事件流读取进度。接口接受请求不代表方向稿、整站或审查已完成。

确认会核对方向计划与网页文件，开始模型执行前也会复核。这个核对不冻结本地目录，无法阻止其他程序在随后执行期间修改文件。

## 素材、参考与当前限制

仍只实现本地静态 HTML/CSS/JavaScript，不增加框架构建、后端数据库、自动部署或付费图像服务。素材限本地文件与原创 CSS/SVG/Canvas；不新接远程字体、外链素材、CDN 或浏览接口。缺少关键素材时应调整方向或补齐素材，不能以破图或未声明的占位图蒙混确认。

参考限用户、宿主、素材库或已提供知识。Agent 不能把已提供的研究描述成自己本轮实时浏览过网站，也不能复制案例的字体、图像或模型。[获奖网页界面学习](./获奖网页界面学习.md)用于提炼字体控制、视觉规则、内容与场景编排的方法，不是本项目的获奖背书。

方向和完整制作都会使用当前 Codex 账号额度；确认方向会启动新一轮执行。模型自审不是独立认证，没有数值化美感分数。截图不能证明所有交互、键盘路径、动态过程、对比度数值或所有屏幕宽度已经合格；自动重渲染也不等于再次完成模型视觉审查。

## 验证状态

2026 年 11 月 14 日本机验证：

- `node --test tests/*.test.mjs`：62 项通过，0 失败、0 跳过。覆盖方向确认前不继续生成、批准后同线程实现、正常局部编辑、重新设计旧编号失效、图片/素材/渲染问题拦截、计划和二进制资源变动、并发确认、停止、隔离预览与完整资源导出。
- Edge 浏览器工作台检查：三张实际方向图正常加载；调整请求包含 `mode:design`，普通修改不带该字段；确认发送当前 `designId`，成功后切换网页预览。关键素材缺失、视图缺失及图片加载失败均不能确认。已确认方向不会再次显示待补齐警告；所有动态说明均按文字呈现。
- 1440 像素电脑、390 与 320 像素手机宽度检查：无页面脚本异常或横向溢出；手机工具栏实际位于设计内容上方。保留[电脑工作台截图](screenshots/v03-workbench-desktop.png)和[手机截图](screenshots/v03-workbench-mobile.png)。
- 真实 Codex 账号测试使用虚构的“字间书会”：新建方向与一次方向调整都生成当前轮计划、电脑首屏/中段/手机截图，状态停在 `awaiting_design`，没有自动展开整站。随后通过工作台实际点击确认，接口接受并开始按确认方向完善网页。
- 确认后的完整实现于本机完成：增加共读方式、轮换问题与问答，保留本地演示报名；七项审查记录格式有效且无未解决项。模型根据初版首屏、全页图和源码修正图注间距与手机辅助文字，宿主对修订版重新渲染，电脑和手机自动检查通过。记录如实注明模型尚未查看修订后的截图，不将自动重渲染称作第二次模型视觉审查。
- 对最终网页另做 19 项 Edge 操作检查并通过：导航与返回页首、演示报名确认/Escape/背景关闭、三个问题循环与回到第一题、四项问答开合及键盘操作。1440 像素电脑和 390 像素手机均无横向溢出，页面脚本异常为 0、数据写入请求为 0；仅记录浏览器自动请求默认图标的可选 404。保留[电脑网页截图](screenshots/v03-site-desktop.png)和[手机截图](screenshots/v03-site-mobile.png)。

程序检查与这次样本不能保证每次生成的审美品质，也不代表已经验证所有页面、交互或屏幕宽度。旧项目重新设计和正常局部编辑的分流由程序测试覆盖；上述真实账号样本验证的是新项目与方向调整、确认路径。
