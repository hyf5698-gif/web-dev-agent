# Agent 如何处理网页美感

美感能力体现在 Agent 生成和修改的网页中。新建页面或明确更换视觉方向时，先做真实可查看的方向稿，用户批准后再扩展完整页面和功能。方向以用途、使用者、真实内容和主要操作为依据；黑底、大标题、衬线或 3D 本身都不代表品质。已有品牌与用户明确的偏好优先；“只改按钮”不会成为重新设计全站的理由。

没有风格偏好也能开始。Agent 应选择适合任务的默认方案，用日常语言简要解释关键选择；只有缺失信息会实质改变功能、内容真实性或范围时才继续询问。它不要求新手先提供一套设计术语。

用户明确要求换美感方向时，Agent 应重新考虑构图、字体、主视觉材料和页面节奏，保留真实内容及有效功能，并更新方向稿与设计记录。已有的审查状态只代表当时的模型判断，不能作为拒绝用户风格反馈的依据。

## 七项观察维度

| 维度 | 实际关注什么 |
| --- | --- |
| 用途与表达 `intent` | 受众能否认出主题、理解价值，并找到下一步。内容不能依靠编造的客户、数字或评价建立可信度。 |
| 信息层级 `hierarchy` | 阅读顺序、内容分组和主要动作是否清楚，重点与次要信息是否有合理区别。 |
| 字体与阅读 `typography` | 标题、正文、导航、图注和数字的角色；字面率、笔画密度、字重、字距、中西文基线、深浅底的视觉重量，以及中文标点、行长和自然断行。 |
| 色彩与对比 `palette` | 颜色是否有明确用途；文字、按钮、边界和焦点是否可辨；状态是否兼有文字或形状提示。 |
| 构图与留白 `composition` | 网格与对齐；主图和标题的主次、比例、裁切和视觉重心；不同章节是否承担有区别的视觉任务。 |
| 视觉个性 `identity` | 字体、图形、素材与运动是否服从同一方向；关键资产的质量及主体、光线、材质、空间和观看尺度是否相符。 |
| 移动端与操作 `mobile` | 内容如何重排；文字、触控、导航、状态反馈与主要动作是否容易使用，有无溢出或遮挡。 |

这些维度用于引导判断，不规定所有网页都使用某种颜色、字体或布局。例如，阅读工具可以安静克制，活动页可以更有表现力；同一构图是否合适，取决于它承载什么内容。视觉个性可以来自一个恰当的图形、排版节奏或内容组织，不需要每页堆满装饰。

## 先确认方向，再完成页面

方向稿会实际写入 `index.html`。展示型页面通常包含桌面首屏、一个代表性中段，以及手机首屏和该区域的响应式重排；工具、工作台等任务页面可用一个主要任务区域说明方向，不强加营销首屏或宣传章节。已有网站仅在相关代表区域试方向，保留其余内容和有效交互，不能将整站替换成缺项的占位稿。

项目的 `DESIGN.md` 用简短文字记录一句艺术方向、字体角色与中文光学校正、关键资产来源和就绪程度、图文比例与裁切、章节强弱以及运动的触发和作用。`DESIGN_PLAN.json` 严格使用宿主定义的结构，保存需要确认并延续的设计计划；指导文本不另定一套结构。示意素材、覆盖范围和剩余工作要明确说明，方向稿不能被称为成品。

用户查看真实方向稿后，可以批准或要求调整。收到明确批准，Agent 才依照计划完成其余静态页面内容与功能；完成阶段继续使用已确认的字体关系、材质、构图与节奏，避免补齐内容时退回重复的通用版式。推翻方向的新要求回到方向确认；范围明确的局部编辑不借机重设全站。批准前不建设完整网站或后端。当前实现仍限本地静态 HTML/CSS/JavaScript。

素材限已有本地文件或原创 CSS/SVG/Canvas。关键资产应能支撑预定构图和显示尺度，素材不足时调整表达方式，不用破图或假装占位资产已经完成。不会新增远程字体、CDN、付费图像服务或浏览接口。运动先解释作用，再实现触发与变化，静态构图和 `prefers-reduced-motion` 下的体验也应成立。

## 研究如何进入设计判断

[获奖网页界面学习](./获奖网页界面学习.md)提供已核实案例与观察边界。Exat 对应字形和画面边界的精确关系，Dropbox 对应字体、图形与反馈的一致规则，Büro 对应具体内容对品牌表达的支撑，Symphony 对应场景、观看距离和章节时间的编排。这些是方法参考，不是要求模仿外观，也不授权复制字体、图片、模型或代码。

Agent 只能引用用户、宿主、素材库或已提供知识中的参考，不能据此声称本轮实时浏览过案例。中文页面需要按实际字形重新处理字面、笔画密度、间距、标点和断行，不能直接照搬拉丁字母的尺度。各章节也应围绕内容改变视觉任务，而非重复同一种大图、标题和说明。

## 真实渲染后的审查

宿主渲染电脑与手机页面，将真实截图和自动报告交给模型审查。审查先辨明方向稿或完整实现，再逐项记录两种视口中的具体观察，说明看到什么、在哪里、对用途有什么影响。方向稿不因尚未批准建设的其余章节而被判为成品缺陷。

审查会具体查看字形与间距的光学关系、标题和图像的主次及裁切、关键资产的清晰度与材质环境、不同章节的节奏，以及手机端如何重排。根据影响选择至多三项必要修正，保护用户风格、已批准方向和有效交互。修正写回源码和 `DESIGN.md`，宿主再对改过的版本执行渲染检查。

运行报告中的加载失败、脚本错误和横向溢出等属于自动检查的事实。层级是否清楚、风格是否合适、构图是否协调属于基于需求和图片的设计判断，可能因受众偏好而有不同结论。没有数值化“美感分数”，也不能用运行无错误证明页面漂亮。

截图只支持它呈现的范围。未查看全页图就不能声称已审查全页；未实际操作或测量，就不能声称所有交互、键盘路径、动效、对比度数值及屏幕宽度都已验证。修改后的自动重渲染也不等于又完成了一次模型视觉审查。最终记录应明确这些边界，保留需要人工体验的部分。

指导文本位于 `server/design-guidance.mjs`。它约束 Agent 的工作方法和证据表达，不是独立设计师认证，也不保证每次产出都符合每个人的审美。
